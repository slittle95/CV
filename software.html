Project Highlights

Measurement and Analysis Console

This program began as a simple dashboard summarizing several SharePoint custom lists in a Power BI dashboard. By the end of my time with it, it connected more than a dozen SharePoint sites and eight Power BI reports using more than twenty Cloud flows.

  • Complete redesign of the structure from simple filters to measures accessing parameters and a date table allowed for historical views.
  • Each program manager had their own dashboard that was filterable by project.
  • Each back office department had their own page in a dashboard that covered standard metrics as well as department-specific ones using a variety of visuals, including clustered column chart, pie chart, gauge, and card. This dashboard was exported monthly as an image and stored on SharePoint.
  • Filterable quarterly, monthly, and year-to-date dashboards displayed all the information together in card visuals for executive management.
  • Power Apps embedded in departmental SharePoint pages allowed department heads to submit the metrics that could not be collected from their SharePoint lists. These metrics were then automatically routed for approval before being stored.
  • Quarterly, a report for each program manager and department head was automatically generated from a template. Information from their SharePoint sites was scraped and included in the report. The only manual work remaining was to explain any outliers.

AutoRPT: Optimize, Document, & Expand

AutoRPT is a machine learning-based tool using spaCy, Torch, TensorFlow, pandas, and numpy to automatically annotate a sound file for prosody.

When I joined the Experimental Linguistics Lab, the AutoRPT software was a collection of extremely loosely coupled Python modules with almost zero comments. In order to understand the program, I followed the workflow step by step and made note of what data structures were being passed to which modules. Most of them were arrays and dictionaries containing all the data for the relevant sound file. I rewrote the system to be object-oriented instead, passing a SpeakerFile object between modules instead of dictionaries. Before I called it done, I made sure to supply every function with a docstring comment so no one else would be in this position! As new uses cases for the data appeared over the course of our research, I took advantage of the SpeakerFile class to write new functions that would cut up the sound files into individual utterances.
